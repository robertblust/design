# A key line Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A section's one point can be lifted out of its paragraph as a key line, and blust.ch's first post uses it five times, with a conclusion line, no section dividers and a quieter "Rests on".

**Architecture:** `.keyline` joins the `lines` block in the design package, which `lib/assemble.mjs` already writes into every site's `page.css`; that is a minor release. blust.ch re-pins it, and the post changes its own inline styles and text, then runs the German roles on the values that changed.

**Tech Stack:** the `@robertblust/design` package (node, `node --test`), static HTML and CSS on blust.ch, the site's `npm run design | og | sitemap | verify` (Playwright), the vendored conventions roles for German, `gh`.

**Spec:** `docs/superpowers/specs/2026-09-26-a-key-line-design.md` in robertblust/design, on the `key-line` branch.

## Global Constraints

- Every shell starts with `export PATH=/opt/homebrew/bin:$PATH` (node and gh live there).
- Design work happens in the worktree `/Users/rob/git/robertblust/design-key-line` on branch `key-line`; the site's in `/Users/rob/git/robertblust/robertblust.github.io-key-line` on branch `key-line`, created in Task 3. Never commit in the clones.
- Never edit `page.css`, `tokens.css` or any other generated file in the site: `npm run design` overwrites it.
- The key line's rule, verbatim: `.keyline{margin:.6rem 0 1.4rem; max-width:54ch; font-size:1.2rem; font-weight:500; line-height:1.45; color:var(--c-firm); text-wrap:balance}`, in the body face, with no border.
- At most one key line per section, none in a section with a `.conclusion`. The element is `<p class="keyline">`, never a `<blockquote>`.
- Commits and pull request bodies are in the git register of `conventions/WRITING.md`: prose, no headings or bullets, ending `Verified: …`, then `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` on commits and `🤖 Generated with [Claude Code](https://claude.com/claude-code)` on pull request bodies.
- A pull request is opened and then the agent stops. Merging, tagging and deleting branches happen only on Rob's explicit word, and a merge uses `gh pr merge --merge`.
- The release number is the next minor after `version` in design's `package.json` on `origin/main` at execution time. Read it, never assume it; this plan writes it as `X.Y.0`.
- A local server is started on a free port, recorded by PID, and stopped by that PID only.

## Review Focus

- The post's prose rule outranks `.keyline`. `.post p` (0,1,1) beats `.keyline` (0,1,0), so without the `:where` exclusion a key line comes out dim, at 16px and 70ch. Task 4 measures a key line's computed style.
- The `:where` exclusion must keep the old weight. Written as `:not(…)`, it rises to (0,2,1) and overrides `.post .rests li p{margin-top:.3rem}`, which opens the gap under each "Rests on" title. Task 4 measures that gap.
- Other `.conclusion` pages do not move. The cost page (`/talks/deciding-well/cost/`) carries two conclusions, and the release only adds a rule. Task 3 diffs their computed style before and after the re-pin.
- The German view shows the key lines in German. Each new element needs its own id and `data-de`, or the language switch leaves English behind. Task 5's `translates` and `design german stale` catch that.
- On a phone the key lines wrap balanced and nothing scrolls sideways. At 390px the `max-width:100%` media rule has to leave `.keyline` alone. Task 4 screenshots 390px and verify's `mobileNav` runs.
